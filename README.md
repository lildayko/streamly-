# Streamly — прототип агрегатора видеоплатформ

Адаптивный веб-прототип единой ленты видео и стримов. В текущей версии используются демонстрационные карточки, а поиск, фильтрация, навигация и сохранение видео работают локально в интерфейсе.

## Требования

- Node.js 20.9 или новее
- npm

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000.

## Что уже работает

- Адаптивный интерфейс для широких и мобильных экранов
- Поиск по названию, автору, категории и платформе
- Фильтр по платформе
- Разделы «Для тебя», «Подписки», «В эфире», «Сохранённое»
- Добавление и удаление видео из сохранённого в текущем состоянии приложения
- Демонстрационные уведомления
- Пример общей модели VideoItem для нормализации контента

## Важно

Это frontend-прототип, а не готовый агрегатор с реальными интеграциями. Данные карточек демонстрационные. Реальные источники требуют отдельной серверной интеграции, проверки актуальной документации и правил платформ, OAuth-настройки, обработки квот и безопасного хранения токенов. Не размещайте секретные API-ключи в клиентском коде.

## Подключение YouTube, Twitch и VK Видео

1. Скопируй `.env.example` в `.env.local` в корне проекта.
2. Заполни ключи в `.env.local`:
   - `YOUTUBE_API_KEY` — создай проект в [Google Cloud Console](https://console.cloud.google.com/), включи YouTube Data API v3 и создай API key.
   - `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET` — зарегистрируй приложение в [Twitch Developer Console](https://dev.twitch.tv/console/apps). Сервер получает app access token автоматически.
   - `VK_ACCESS_TOKEN` — токен VK API с доступом к поиску видео. Доступность `video.search` зависит от типа токена и разрешений приложения.
3. Перезапусти сервер разработки после изменения переменных окружения: останови `npm run dev` сочетанием Ctrl+C и запусти снова `npm run dev`.
4. В Streamly введи запрос в поиске и нажми Enter или «Найти». Результаты объединятся в общую ленту; на карточке можно открыть оригинал на платформе.

**Безопасность:** `.env.local` не публикуй и не отправляй в чат. Ключи читаются только серверным маршрутом `/api/search`, а не браузером. Если ключ случайно оказался публичным, отзови его и создай новый.

**Текущее ограничение:** это поиск по запросу, а не персональная лента подписок. Для персональных подписок потребуется отдельная OAuth-авторизация пользователей на каждой платформе и хранение токенов на сервере. VK API может ограничивать поиск в зависимости от выданного токена и настроек приложения.

## Обновление ленты и плеера
- Главная лента при запуске автоматически пытается загрузить до 50 реальных результатов YouTube через `YOUTUBE_API_KEY` (поисковый запрос «популярные видео»).
- Поиск использует до 50 результатов YouTube за запрос; Twitch/VK ограничены возможностями соответствующих API и правами токена.
- Нажатие на YouTube-видео открывает встроенный YouTube-плеер и панель рекомендаций Streamly. Twitch открывается во встроенном плеере при корректном `parent` домене. Не все ролики VK разрешают встраивание, поэтому для них может отображаться кнопка перехода к оригиналу.
- Для рабочего продакшена ограничьте API-ключ YouTube по API и HTTP referrer/IP в Google Cloud. Никогда не добавляйте ключ в клиентский код.

## Подключение личного YouTube-аккаунта

Для чтения подписок пользователя Streamly использует OAuth 2.0 с разрешением `youtube.readonly`. API key сам по себе не даёт доступ к личным подпискам.

1. В Google Cloud Console настрой OAuth consent screen и создай OAuth Client ID типа **Web application**.
2. Добавь Authorized redirect URI: `http://localhost:3000/api/youtube/callback`.
3. Заполни `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET` и `YOUTUBE_REDIRECT_URI` в `.env.local`.
4. Перезапусти `npm run dev` и нажми «Подключить YouTube» в боковой панели Streamly.
5. После согласия пользователя раздел «Подписки» сможет показать свежие видео с каналов, на которые пользователь подписан.

Примечание: YouTube Data API не предоставляет официальный API для получения готовой главной ленты персональных рекомендаций YouTube. Streamly формирует подборку из новых видео каналов пользователя; это не копия внутреннего алгоритма рекомендаций YouTube. Для публичного запуска OAuth consent screen может потребовать настройки/проверки в Google Cloud.

## Обновление синхронизации подписок

- `/api/youtube/recommendations` проходит по страницам YouTube Subscriptions API (до 100 страниц по 50 записей) вместо чтения только первой страницы.
- Для каждого найденного канала загружается его официальный uploads playlist и до 50 последних опубликованных видео. Это избегает лимита поиска в 5 результатов и не тратит отдельный поиск на каждый ролик.
- В разделе «Подписки» отображается список каналов; нажатие на канал открывает его видео. При подключённом YouTube лента «Для тебя» использует видео из подписок как основу.
- YouTube Data API не отдаёт все исторические видео одним ответом: для полного архива понадобится постраничная загрузка uploads playlist через `nextPageToken`. Текущая синхронизация загружает первые 50 последних видео каждого канала.

## Исправления логики лент

- Поиск использует отдельную выдачу и не подменяется видео подписок. Поздний ответ предыдущего поиска игнорируется.
- Сохранённое хранит карточки в `streamly-saved-items` в браузере. Оно не зависит от текущей выдачи и сохраняется после перезагрузки. Старые идентификаторы из предыдущей версии сохраняются, но восстановить отсутствующие метаданные автоматически нельзя.
- Короткие YouTube-видео (известная длительность больше нуля и меньше 165 секунд) выделяются в Shorts. Это фильтр длительности, не подтверждение официального формата Shorts. Видео с неизвестной длительностью видны в обычной ленте; поиск, история и сохранённое показывают оба формата.
- «Загрузить ещё» использует курсоры YouTube/Twitch и offset VK, добавляет результаты без дублей и исчезает в конце выдачи.
- Синхронизация подписок ограничена пятью одновременными загрузками каналов. Частичные ошибки видны пользователю; ранее загруженные видео недоступных каналов сохраняются в текущем интерфейсе. Список каналов доступен даже без видео.
- Успешные подписки кэшируются в памяти на две минуты отдельно для каждой сессии. «Обновить» обходит кэш.
- Публичный поиск объединяет одинаковые запросы и кэширует их на минуту: максимум 100 записей, 8 одновременных обращений и 60 новых обращений к платформам в минуту на процесс. Для нескольких серверов нужен общий лимитер/кэш; эти ограничения не гарантируют сохранность суточной квоты.
- Twitch-плеер использует текущий hostname и логин канала из оригинальной ссылки.

### Проверки

```bash
npm ci
npm run lint
npm run build
npm test
```

Браузерные тесты используют системный Chromium, если он доступен. Иначе установите браузер командой `npx playwright install chromium`; путь к своему бинарному файлу можно указать через `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. Тесты подменяют ответы внешних платформ и не требуют реальных ключей. Они не проверяют работоспособность настоящих OAuth-реквизитов и доступность API вашего приложения.

Для запуска собранного приложения: `npm start`. Учётные данные задавайте через окружение или локальный `.env.local`, который исключён из Git. `package-lock.json` фиксирует установленные зависимости.

### Что ещё требуется для публичного сервиса

OAuth-токены пока остаются в HttpOnly cookies, как в исходном прототипе. Серверное хранилище сессий и токенов, отзыв доступа, общая база библиотеки между устройствами и постепенная фоновая синхронизация большого числа подписок требуют следующего этапа. Первичная загрузка большого аккаунта всё ещё может быть долгой. Демо-элементы интерфейса (Plus, уведомления, часть статистики) пока не подключены к реальному серверу.

## Трансляции и непрерывная прокрутка

Выбор платформы теперь загружает её выдачу. Раздел «В эфире» запрашивает активные YouTube-трансляции (`eventType=live`) и текущие Twitch-эфиры (`helix/streams`), а не фильтрует обычную YouTube-ленту. Поиск Twitch по запросу использует `search/channels` с `live_only=true`. Для Twitch по-прежнему нужны `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET`; без них интерфейс показывает причину отсутствия данных. Учётная запись YouTube не предоставляет доступ к Twitch API.

Лента, поиск и список рекомендаций в плеере автоматически подгружают следующие страницы при достижении конца списка. Число рекомендаций больше не обрезается до 8/20. Видео подписок подгружаются за пределами первых 50 на канал. В Shorts доступны колесо прокрутки, вертикальный свайп и кнопки навигации; у конца загруженной подборки запрашивается следующая страница. Фактический объём доступных видео определяется API платформы. При ошибке автозагрузка приостанавливается, остаётся кнопка повторной попытки.

Три карточки статистики и вымышленное число эфиров удалены. В плеере список рекомендаций прокручивается вместе с окном, без отдельной ограниченной области. Проверки интеграций используют подменённые ответы API; реальное воспроизведение зависит от выданных ключей, доступности платформ и разрешения встраивания у конкретного канала.

## Привязка личного Twitch

Используются те же `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET`, которые нужны для публичных эфиров. В [Twitch Developer Console](https://dev.twitch.tv/console/apps) добавь в OAuth Redirect URLs точный адрес `http://localhost:3000/api/twitch/callback` (для другого домена укажи его адрес и задай `TWITCH_REDIRECT_URI`). Перезапусти сервер и нажми «Подключить Twitch» в боковом меню.

Streamly запрашивает только `user:read:follows`, показывает имя аккаунта и активные эфиры отслеживаемых каналов в разделе «Подписки». Это отслеживаемые каналы, а не платные подписки Twitch. Access/refresh-токены хранятся в HttpOnly cookies, обновление access-токена выполняется сервером. «Отключить» удаляет локальную сессию Streamly; полный отзыв разрешения приложения доступен в настройках подключений Twitch. На публичном домене используй HTTPS.

## Собственные рекомендации Streamly

«Для тебя» и Shorts больше не подменяются выгрузкой подписок. Сервер подбирает публичных кандидатов по выбранным интересам и словам из недавней истории, добавляет темы для открытия нового контента, ранжирует совпадения, повышает авторов вне известных подписок и исключает уже просмотренные ролики. Авторы чередуются, чтобы один канал не занимал начало подборки. Под карточками указана тема подбора; интересы можно менять кнопками над лентой, они сохраняются в браузере. Пагинация чередует темы и продолжает выдачу каждой платформы, не повторяя одну первую страницу. В Twitch подбор по теме ищет категории и использует эфиры соответствующей категории; при отсутствии категории показывает популярные эфиры.

Это собственный эвристический подбор Streamly, а не импорт главной страницы YouTube/Twitch: официальные API не предоставляют их персональную рекомендательную ленту. История — просмотры внутри Streamly, не история аккаунта YouTube/Twitch. Без истории и выбранных интересов используются стартовые темы. История и темы передаются серверу Streamly для подбора, публичный кэш хранит только ответы платформ; персональные результаты помечены `private, no-store`. Обычная лента подписок остаётся в «Подписках».
